## 参赛流程概览

参赛者可以按下面的顺序理解整个比赛：

1. 在头歌平台注册并报名。
2. 组队或单人成队，每队 1-3 人，其中组队要求为 2-3 人，单人成队也允许。

## 模型与代码审核

只有进入 A 榜前 50 名的战队，并通过代码审查，才能进入 B 榜。决赛团队遴选以 B 榜成绩为准。

组委会会对 B 榜前列队伍进行模型和代码审核，要求在计图平台上复现榜单最优成绩。通过审核的前 10 名队伍进入决赛答辩。

以下情况会导致成绩无效：

- 未提交代码。
- 使用预训练模型但未提供预训练模型来源。
- 未基于计图框架实现。
- 代码无法复现提交结果。
- 代码与其他战队雷同。

这一部分意味着参赛时需要保存训练配置、依赖版本、随机种子、数据处理流程和推理脚本。只追求提交结果而不保留可复现流程，会在审核阶段产生风险。

## 热身赛一：基于 Cora 引文网络的节点分类

页面当前“赛题说明”中显示的是“计图挑战赛赛道一热身赛”。

这个热身赛的目标是验证参赛者能否使用 JittorGeometric 完成基础图神经网络任务。它更像正式赛题前的准入练习：任务规模相对明确，评测指标是准确率，提交格式固定。

### 赛题介绍

本赛道使用 JittorGeometric 图神经网络库，在基于 Cora 的引文网络数据集上训练 GCN（Graph Convolutional Network）模型，完成节点分类任务。

### 赛题内容

赛题提供一个基于 Cora 的引文网络数据集，文件名为 `data/cora.pkl`，已经包含在发布包中。

参赛选手需要基于 JittorGeometric 库，使用 GCN 模型完成节点分类任务，对测试集中的节点预测所属类别。

### 任务说明

- 输入：引文网络图数据 `data/cora.pkl`
- 输出：测试集节点预测分类，保存为 JSON 文件
- 输出 JSON 格式：字典形式，key 为节点编号，value 为预测类别
- 注意：测试集节点标签为 `-1`，真实标签已隐藏，选手需要通过训练模型进行预测

### 数据集简介

Cora 数据集信息：

- 节点数：2708，每个节点代表一篇论文
- 边数：5429，边代表引用关系
- 特征维度：1433，使用词袋特征
- 类别数：7

数据集字段：

- `x`：节点特征矩阵，numpy array，shape 为 `2708 x 1433`
- `y`：节点标签，numpy array，shape 为 `2708`；训练集和验证集标签完整，测试集标签为 `-1`
- `edge_index`：边列表，numpy array，shape 为 `2 x num_edges`
- `train_mask`：训练集掩码
- `val_mask`：验证集掩码
- `test_mask`：测试集掩码
- `num_classes`：类别数
- `num_features`：特征维度

### 示例代码

赛题提供数据集与示例代码框架，包括数据加载、模型定义、训练步骤等功能。

选手可以基于示例代码，填充注释为 `TODO` 的部分完成赛题。

### 评测方式

评测程序会加载选手提交的预测结果 `result.json`，与测试集真实标签进行对比，计算分类准确率 Accuracy。

测试集准确率大于等于 `0.70` 即为通过。

### 提交格式

提交文件为 `result.zip`，结构如下：

```text
result.zip
├── gcn.py
└── result.json
```

其中：

- `gcn.py`：模型代码和训练代码
- `result.json`：测试集预测结果

`result.json` 示例：

```json
{
  "1708": 0,
  "1709": 1,
  "1710": 3
}
```

key 为测试集节点编号，字符串格式；value 为预测类别编号，整数范围为 `0-6`。

## Jittor 框架说明

Jittor 是一个基于即时编译和元算子的高性能深度学习框架。框架在即时编译的同时集成了 Op 编译器和调优器，可以为模型生成定制化高性能代码。

Jittor 包含丰富的高性能模型库，覆盖图像识别、检测、分割、生成、可微渲染、几何学习、强化学习等方向。

Jittor 前端语言为 Python，接口设计包含模块化和动态图执行；后端使用高性能语言进行深度优化。

页面提供的参考入口包括：

- Jittor 官网
- Jittor 教程
- Jittor 模型库
- Jittor 文档
- GitHub 开源仓库
- Gitee 开源仓库

## 为什么比赛强调 Jittor

该比赛的核心目的之一是推动国产深度学习框架生态建设，所以 Jittor 不是可选项，而是参赛实现的硬性要求。参赛代码如果不是基于 Jittor 实现，即使模型思路正确，也会被判为无效成绩。

## Jittor 环境要求

- 操作系统：Ubuntu 16.04 或更高版本，或 Windows Subsystem for Linux（WSL）
- Python：3.7 或更高版本
- C++ 编译器至少满足以下之一：
  - g++ 5.4.0 或更高版本
  - clang 8.0 或更高版本
- GPU 编译器可选：nvcc 10.0 或更高版本
- GPU 加速库可选：cudnn-dev

注意：Jittor 在 Windows 上通过 WSL 方式运行。页面提示 WSL 版本目前尚不支持 CUDA。

## Jittor 安装方式

### Docker 安装

```bash
# linux CPU only
docker run -it --network host jittor/jittor

# linux CPU and CUDA
docker run -it --network host --gpus all jittor/jittor-cuda

# mac/windows
docker run -it -p 8888:8888 jittor/jittor
```

### Pip 安装

```bash
sudo apt install python3.7-dev libomp-dev
python3.7 -m pip install jittor
python3.7 -m jittor.test.test_example
```

也可以从 GitHub 安装最新版本：

```bash
python3.7 -m pip install git+https://github.com/Jittor/jittor.git
```

如果测试运行通过，即表示安装完成。

### 手动安装

安装编译器：

```bash
# g++
sudo apt install g++ build-essential libomp-dev

# 或 clang++-8
wget -O - https://raw.githubusercontent.com/Jittor/jittor/master/script/install_llvm.sh > /tmp/llvm.sh
bash /tmp/llvm.sh 8
```

安装 Python：

```bash
sudo apt install python3.7 python3.7-dev
```

安装并运行 Jittor：

```bash
git clone https://github.com/Jittor/jittor.git
sudo pip3.7 install ./jittor
export cc_path="clang++-8"
python3.7 -m jittor.test.test_example
```

### CUDA 设置

```bash
export nvcc_path="/usr/local/cuda/bin/nvcc"
python3.7 -m jittor.test.test_cuda
```

在 Python 中启用 CUDA：

